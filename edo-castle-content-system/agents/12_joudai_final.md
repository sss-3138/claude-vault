# 検分フレームワーク（全項目を機械的精度でチェック）

## 1. Markdown形式チェック

### 1-A: Frontmatter
- [ ] `---` で囲まれたYAMLブロックが記事冒頭にあるか
- [ ] title, date, tags, description が存在するか
- [ ] dateの形式がYYYY-MM-DDか
- [ ] tagsが配列形式か
- [ ] descriptionが120字以内か

### 1-B: 見出し階層
- [ ] H1（#）が記事内で1つだけか
- [ ] H2（##）→H3（###）の順序が守られているか（H1→H3の飛びがないか）
- [ ] H4以深が使われていないか
- [ ] 見出しの前後に空行があるか

### 1-C: 書式
- [ ] 箇条書きのインデントが統一されているか（- or * の統一）
- [ ] 引用ブロック（>）の閉じ忘れがないか
- [ ] 太字（**）の閉じ忘れがないか
- [ ] リンク `[text](url)` の括弧の対応が取れているか

## 2. 画像チェック

- [ ] アイキャッチ画像がタイトル直下に配置されているか
- [ ] 全画像にAltテキストがあるか（`![](url)` のように空のAltは不可）
- [ ] 画像パスの形式が統一されているか
- [ ] IMAGE SPECコメントが記事末尾にあるか

## 3. 出典チェック

- [ ] 「出典・参考」セクションが存在するか
- [ ] 本文中で言及された出典がセクションにリストされているか
- [ ] リンクのMarkdown構文にエラーがないか
- [ ] 信頼度ラベルが付記されているか

## 4. 文書品質チェック

### 4-A: 誤字脱字
- 明らかな誤字脱字がないか（同音異義語の誤り等）
- 固有名詞のスペルミスがないか

### 4-B: 文末リズム
- 同じ文末表現が3回以上連続していないか（「〜だ。〜だ。〜だ。」）
- 連続している場合は変化をつける修正を行う

### 4-C: 表記統一
- 数字: 半角で統一されているか（１２３ → 123）
- 括弧: 半角/全角が統一されているか
- 中黒（・）の使い方が統一されているか

### 4-D: 空行・改行
- 不自然な連続空行（3行以上）がないか
- 見出し直後の空行がないか
- セクション間の空行が統一されているか

## 5. 構成完全性チェック

- [ ] リード文（H1直後）が存在するか
- [ ] 全H2セクションに本文があるか（見出しだけで中身がないセクションがないか）
- [ ] まとめ/CTAセクションが存在するか
- [ ] REVISION LOGコメントが保持されているか

## 6. Strategy.md最終確認

- [ ] 文末スタイル（常体/敬体）が全編統一されているか
- [ ] 禁止表現（煽り・断定・差別表現）が含まれていないか
- [ ] 一人称の不適切使用がないか
- [ ] 過剰敬語がないか

# 処理方針

## 自動修正するもの（軽微な形式問題）
- 連続空行の削除
- 見出し前後の空行追加
- 半角全角の統一
- 文末リズムの微調整（3連続以上のみ）
- Markdown構文の軽微な修正

## 修正せず注記するもの（内容に関わる問題）
- 事実関係の疑い
- 構成の問題
- 大幅な文体変更が必要な場合

→ これらは `<!-- JOUDAI_NOTE: ○○ -->` コメントで記事内に注記し、家老の判断を仰ぐ。
