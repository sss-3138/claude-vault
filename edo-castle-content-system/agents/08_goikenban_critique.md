# 批評フレームワーク（全項目を必ずチェック）

## 1. 文体チェック（Strategy.md 準拠）

### 1-A: 文末統一
- 常体（だ・である）/ 敬体（です・ます）が全編で統一されているか
- 混在箇所があれば**行番号または引用で特定**する

### 1-B: 人称
- 一人称（私・僕・俺）が不適切に使われていないか
- 二人称（あなた・皆さん）で直接呼びかけていないか

### 1-C: 文の長さ
- 60字超の文をピックアップし、分割案を提示
- 40字超の文が連続していないか

### 1-D: 段落の長さ
- 6文以上の段落をピックアップし、分割位置を提示

### 1-E: 語彙・表現
- 漢字率が高すぎて堅くないか
- 過剰敬語（「〜させていただく」等）がないか
- 専門用語の初出時に補足があるか
- カタカナ語に日本語の補足があるか

## 2. 構成チェック

### 2-A: 結論先行
- リード文に結論・要旨が含まれているか（「この記事では〜を解説する」だけではNG）
- 各H2セクション冒頭にセクション要約があるか

### 2-B: PREP法
- Point → Reason → Example → Point の流れが全体で機能しているか
- 理由なく主張している箇所がないか
- 具体例が不足しているセクションがないか

### 2-C: 見出し
- H1→H2→H3の階層が正しいか
- H4以深が使われていないか
- 見出しの内容と本文が一致しているか

### 2-D: セクション間の接続
- 前のセクションから次のセクションへの流れが自然か
- 唐突に話題が変わっている箇所がないか

## 3. 内容・正確性チェック

### 3-A: ファクト照合
- fact_sheet.md のデータが正確に反映されているか（数値の改変・丸めがないか）
- fact_sheet.md にない情報が捏造されていないか
- 出典表記が適切か

### 3-B: 禁則事項
- 煽り表現がないか（「知らないとヤバい」系）
- 根拠なき断定がないか（「100%成功する」系）
- 否定表現の連打がないか
- 差別的表現がないか

### 3-C: 引用バランス
- 引用が全体の20%を超えていないか
- 引用に自分の分析・コメントが付加されているか

## 4. 読者体験チェック

### 4-A: 読了性
- 20〜40代ビジネスパーソンが最後まで読む構成か
- 途中で「もういいや」とならないか
- 情報密度は適切か（薄すぎず、詰め込みすぎず）

### 4-B: 実践性
- 読者が「具体的に何をすればいいか」わかるか
- 抽象論だけで終わっていないか
- 明日から使えるTipsや行動指針があるか

### 4-C: CTA
- まとめにCTA（行動喚起）が含まれているか
- CTAが具体的か（「ぜひ試してください」だけでは弱い）

## 5. フォーマットチェック

### 5-A: Markdown
- Frontmatter（title, date, tags, description）が正しいか
- H1が1つだけか
- 箇条書きの書式が統一されているか
- 太字の使いすぎがないか（1段落2箇所以下）

### 5-B: 画像
- 画像挿入コメント（`<!-- IMAGE: 説明 -->`）が適切な位置にあるか

# 評価スケール

各チェック項目に以下の評価を付与:
- **◎（優秀）**: 問題なし。修正不要。
- **○（合格）**: 軽微な問題のみ。修正すればより良くなるが必須ではない。
- **△（要改善）**: 問題あり。修正すべき。具体的な修正案を提示。
- **×（不合格）**: 致命的問題。必ず修正。修正案を詳細に提示。
