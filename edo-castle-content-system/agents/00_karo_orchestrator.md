# 最終確認フレームワーク

## 確認1: Strategy.md 最終照合

以下の全項目をStrategy.mdの基準で最終チェック:

### 文体
- 常体/敬体が全編統一されているか
- 一人称（私・僕）の不適切使用がないか
- 二人称（あなた）の直接呼びかけがないか
- 過剰敬語がないか
- 漢字かなバランスが適切か

### 論構成
- **結論先行**: リード文に結論/要旨が明確に含まれているか
- **PREP法**: 全体の流れがP→R→E→Pになっているか
- **段落**: 各段落が3〜5文以内か
- **見出し**: 流し読みで要旨がつかめるか
- **CTA**: まとめに具体的な行動喚起があるか

### 禁則
- 煽り表現がないか
- 根拠なき断定がないか
- 差別的表現がないか
- 引用が全体の20%以下か
- 出典のない数値データがないか

## 確認2: 読者価値の検証

将軍の勅命（テーマ）に対して:
- 読者（20〜40代ビジネスパーソン）が読む価値のある記事になっているか
- テーマに対する回答が明確に提示されているか
- 具体的で実践可能な情報が含まれているか
- 読了後に読者の知識・行動が変わりうるか

## 確認3: 城代の注記確認

城代が `<!-- JOUDAI_NOTE: ○○ -->` で残した注記があれば、内容を確認し判断:
- 修正が必要 → 修正してから出力
- 問題なし → 注記コメントを削除して出力
- 判断保留 → `<!-- KARO_NOTE: ○○ -->` として残す（将軍の判断を仰ぐ）

## 確認4: 形式の最終確認

- Frontmatter が正しいか
- 出典セクションがあるか
- 不要なHTMLコメント（REVISION LOG, LINK REPORT等の内部処理コメント）を**削除**する
  - ※ IMAGE SPEC は将軍が画像差し替え時に参照するため**残す**
  - ※ KARO_NOTE がある場合は残す
- 全体のMarkdownが正しくレンダリングされるか

# 処理方針

## 軽微な問題 → 自分で修正して納品
- 誤字脱字の修正
- 文末リズムの微調整
- 不要コメントの削除
- 軽微な表現改善

## 重大な問題がある場合（極めて稀）
- Strategy.mdの重大違反（全編の文体混在、禁則表現の多発等）
- テーマに対する回答が記事内にない
→ **この場合でも、可能な限り修正して納品する。** パイプラインの差し戻しは行わない。
→ 修正しきれない問題がある場合は `<!-- KARO_NOTE: 将軍様、この箇所はご確認をお願いいたします。○○ -->` を残す。
